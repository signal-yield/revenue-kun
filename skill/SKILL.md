# revenue-kun（収益還元クン）Skill

> **免責・用語ガード**
> 本Skillの出力は「収益試算値」であり、鑑定評価による「収益価格」ではありません。
> 合成サンプルPDFで動作確認済みに加え、同一ベンダー系テンプレートとみられる非公開の実物件テキストPDF3件でCLI・Local Web UIからの抽出・Excel生成を確認済みです。
> テンプレート多様性の検証はIssue #21で継続しています。
> 正式な鑑定評価・価格判断・投資判断・法的判断は専門家にご確認ください。
> 欠損値は補完しません（空欄のまま提示します）。

---

## 起動時の絶対命令

本Skill起動時は必ず `python scripts/main.py --excel-output <出力先>` を実行する。
openpyxl を直接呼んで xlsx を生成すること、数式を手書きで再現することは禁止。
エンジン（scripts/）が唯一の計算・出力経路である。

初回実行前に依存ライブラリを導入する：
```
pip install -r requirements.txt --break-system-packages
```

末尾途切れ確認（サンドボックスの誤検知防止）：
```
tail -3 scripts/main.py
tail -3 scripts/revenue_kun/excel_output.py
tail -3 scripts/revenue_kun/pdf_extract.py
```
末尾が正常（`if __name__`／関数の return 等）ならファイルは完全。
独自実装で代替せず、そのまま `python scripts/main.py ...` を実行する。

上記はExcel生成を依頼された場合の絶対命令である。ユーザーが**Local Web UIの起動**を依頼した場合は、`python scripts/main.py` を実行せず、下記「Local Web UI 起動」の分岐に従う。

## Local Web UI 起動

ユーザーが次のように依頼した場合は、CLIでのExcel生成ではなく **Local Web UIの起動** を行う。

トリガー語例：「revenue-kunを起動して」「revenue-kunのWeb UIを開いて」「収益還元クンをブラウザで使いたい」「起動して」「Web UIを開いて」「ブラウザで使いたい」（後者3語は、直前の会話文脈がrevenue-kunである場合に限る）

> **前提**: この分岐は revenue-kun リポジトリ全体（`webui/` ディレクトリを含む）にアクセスできる環境（例：このリポジトリをクローンしたローカル環境でClaude CodeまたはCodexが動作している場合）でのみ有効。claude.ai / Coworkへパッケージ配布された `skill/` 単体（`scripts/` のみ同梱、`webui/` は含まれない）では、この分岐は使用できない。その場合はCLIでの利用のみ案内する。

### 1. 事前確認（重複起動防止）

起動前に、`127.0.0.1:8000` が既に使用中か health check で確認する。

```bash
curl -s http://127.0.0.1:8000/healthz
```

- レスポンスが `{"status":"ok"}` であれば、revenue-kunのLocal Web UIが既に起動中とみなし、**重複起動せず既存プロセスを再利用**する。ユーザーへは「既に起動しています」と伝え、`http://127.0.0.1:8000/` を案内する。
- レスポンスがない、または `{"status":"ok"}` 以外の内容が返る場合（他アプリがポート8000を使用している可能性があり、revenue-kunのWeb UIであると確認できない）は、**その既存プロセスを流用・強制終了しない**。ポート8000が使用できない旨をユーザーへ伝え、別ポートでの起動可否を確認する。

### 2. 起動コマンド

```bash
python -m uvicorn webui.app:app --host 127.0.0.1 --port 8000
```

- リポジトリルート（`webui/` が存在するディレクトリ）で実行する。
- **バックグラウンドで起動**し、Claude Code / Codexの以後の操作をブロックしない。
- **`127.0.0.1`（ループバック）限定でbind**する。`0.0.0.0`や外部・LANへは公開しない。

### 3. 起動後の案内

起動後、health check（`curl -s http://127.0.0.1:8000/healthz`）で `{"status":"ok"}` を確認したうえで、次をユーザーへ案内する。

```
http://127.0.0.1:8000/
```

このWeb UIは**ローカル実行専用**であり、ホスティング型SaaSではない旨を必ず添える。

### 4. 起動失敗時

起動コマンドの終了コードやエラー出力を確認し、失敗原因（依存パッケージ未導入、ポート競合、`webui/` ディレクトリが見つからない等）を要約してユーザーへ伝える。原因を確認せずに「起動しました」と報告しない。

### 5. CLIフローとの関係

この分岐はLocal Web UIの起動のみを扱う。CLIによる`direct_cap.xlsx`生成フロー（`--dry-run` → 本実行、上記「起動時の絶対命令」「入力処理」）はこのセクションの影響を受けず、現状のまま維持する。

## 入力処理

1. アップロードされたレントロール PDF を検出する。
   - claude.ai: `/mnt/user-data/uploads/`
   - Cowork: 指定パス
2. **まず `--dry-run`** を実行し、抽出診断（ユニット数・カラムマップ・必須欠損・欠損セル数）をユーザーに提示する。
3. ユーザーの確認後、本実行で xlsx を生成する。
4. **欠損は補完しない**。`missing_info.md` の要点（どのセルが欠損か）を会話内に要約提示する。

### dry-run コマンド

```bash
python scripts/main.py \
  --assumptions samples/assumptions.sample.yaml \
  --rent-roll-pdf <PDF パス> \
  --output ./out \
  --dry-run
```

### 本実行コマンド

```bash
python scripts/main.py \
  --assumptions samples/assumptions.sample.yaml \
  --rent-roll-pdf <PDF パス> \
  --output ./out \
  --excel-output "./out/収益試算_<物件名>_<YYYYMMDD>.xlsx"
```

## assumptions の扱い（確定仕様）

- 同梱の `samples/assumptions.sample.yaml` を既定として実行する（収入側を自動集計するため）。
- **収益試算 Excel の判断値（空室損失率・貸倒損失率・採用OER／個別費用・資本的支出・還元利回り）は、OER版（E13:E17）・費用詳細版（E13:E16・E19:E24）とも空欄のまま出力**し、ユーザーが Excel 上で手入力する。用途区分・OER・費用の入力はSkill・アプリのいずれからも求めない。
- **会話側で還元利回り等を聞き出さない。提案・例示・初期値設定もしない**（CLAUDE.md §13 厳守）。
  「相場は」「ざっくりで」等を求められても数値を出さず、ユーザー入力に委ねる旨だけ伝える。
- 結果としてOER版E24・費用詳細版E31の収益試算値は、ユーザーが利回りを入れるまで空欄（`IFERROR(.., "")`）。これは仕様。
- OER版と費用詳細版は完全に独立しており、一方の入力値・計算値を他方が参照することはない。どちらを使うか（あるいは両方使うか）はユーザーの判断。

## 出力

成果物: `収益試算_<物件名またはレントロール名>_<YYYYMMDD>.xlsx`

- claude.ai: `/mnt/user-data/outputs/` に置き **present_files で提示**
- Cowork: デスクトップへコピー（MAX_PATH 回避）も可

xlsx には OER版・費用詳細版それぞれ独立した自己計算モデルが入る：
- 収入側（両シートともE5:E9、独立した数式）: レントロールから自動集計・自動算入
- OER版 判断値（E13:E17、採用OER含む）: 空欄（ユーザーが手入力）
- OER版 収益試算値（E24）: `=IFERROR(E23/E17,"")` — 利回り入力まで空欄
- 費用詳細版 判断値・個別費用（E13:E16、E19:E24）: 空欄（ユーザーが手入力）
- 費用詳細版 収益試算値（E31）: `=IFERROR(E30/E16,"")` — 利回り入力まで空欄
- 両シートは互いを参照しない（独立計算）

## 禁止事項

- 還元利回り・空室損失率・経費率・資本的支出の値を提案・例示・初期値設定すること
