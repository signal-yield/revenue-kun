# Claude Skill v0.1 Plan — After LP Publication

## 1. Purpose

Define the scope, constraints, and release criteria for a future **Claude Skill / Claude-assisted
workflow** version of revenue-kun.

This is a **planning document only**.
No Claude Skill has been released. No Python code is modified.
No release or tag is created by this document.

> **重要**: revenue-kun は不動産鑑定評価ではありません。出力される金額は「収益試算値」であり、
> 鑑定評価による「収益価格」ではありません。欠損項目は補完しません。
> qualifying real-world text-based PDF の評価は未完了（Issue #21 open）。
> 実務検証済みとは表記しません。
> Claude Skill リリース済みとは表記しません。

## 2. Definition: Claude Skill / Claude-assisted Workflow in This Project

For the purposes of this document, the following terms are used:

| Term | Meaning |
|------|---------|
| **Claude Skill** | Operator-level instruction set (e.g., CLAUDE.md, `.claude/commands/`, or a packaged Skill file) that directs Claude to assist users in running revenue-kun safely, reviewing outputs, and filling in user-editable Excel fields. |
| **Claude-assisted workflow** | A workflow where Claude orchestrates CLI invocations, reads output files, summarizes missing values, and guides user input — without modifying Python source or making appraisal/advisory claims. |
| **Claude Skill candidate** | The current project state: CLI is functional, Excel output is implemented, but no Skill packaging or release has occurred. |

**What this is NOT**:
- Not a full autonomous appraisal pipeline
- Not a SaaS product
- Not a released Skill available in any marketplace
- Not a replacement for professional judgment (鑑定士・弁護士・税理士)

## 6. Intended User Workflow (Future Claude Skill)

When a Claude Skill or Claude-assisted workflow is active, the intended flow is:

```
1. User provides: rent roll PDF path (or CSV) + assumptions YAML path
      ↓
2. Claude runs: python src/main.py --dry-run  (extraction check)
      ↓
3. Claude reads: extraction_log.json, missing_info.md
   Claude summarizes: what was extracted, what is missing, what user must fill in
      ↓
4. User confirms: extraction looks correct (human checkpoint)
      ↓
5. Claude runs: python src/main.py --excel-output <path>  (full run)
      ↓
6. Claude reads: output/missing_info.md
   Claude lists: which Excel cells the user must fill in manually
      ↓
7. User fills in: vacant-unit rents, expense details, OER assumptions (human checkpoint)
      ↓
8. Claude confirms: which fields were filled, which remain empty
      ↓
9. User reviews revenue estimate — consults professional as needed (human checkpoint)
```

Claude does **not**:
- Recommend a cap rate or vacancy rate value
- Predict or suggest a property value
- Fill in missing rents, expenses, or assumptions on the user's behalf
- Make investment, legal, or tax recommendations

## 7. Required Inputs

| Input | Format | Source | Notes |
|-------|--------|--------|-------|
| Rent roll | text-based PDF or CSV | User-provided | OCR / scanned PDF not supported |
| Assumptions | YAML | `assumptions.sample.yaml` or user-edited copy | Must pass `validate_assumptions()` |

- If `RentRollExtractionError` is raised, Claude surfaces the `failure_reason` and stops

## 9. Allowed Commands

A Claude Skill operating on this project is permitted to run only the following commands:

| Command | Purpose |
|---------|---------|
| `python src/main.py --dry-run ...` | Extraction check without computation |
| `python src/main.py --excel-output ...` | Full run with Excel output |
| `python src/main.py --version` | Version check |
| `python -m pytest` | Test suite (verification only) |

**Allowed read operations** (for summarizing output to the user):
- Read `output/missing_info.md`
- Read `output/extraction_log.json`
- Read `assumptions.sample.yaml`

**Prohibited operations** (must not be run by a Claude Skill):
- Modifying any `.py` file in `src/`
- `pip install` / package upgrades
- `git push`, `git commit` (unless explicitly instructed by user)
- Deleting or overwriting the user's rent roll PDF
- Writing to `output/` paths other than those specified in `--excel-output` and `--output`
- Running any command that performs OCR on scanned images

## 11. Error Handling Policy

| Error type | Skill behavior |
|-----------|---------------|
| `RentRollExtractionError` | Surface `failure_reason` to user. Stop. Do not attempt workaround or OCR fallback. |
| `AssumptionsError` | Surface validation message. Ask user to edit assumptions YAML. |
| `OSError` (file/permissions) | Surface message. Do not retry destructively. |
| Missing required fields | List missing fields from `missing_info.md`. Ask user to provide values manually. |
| Exit code ≠ 0 | Surface stderr output. Do not proceed to Excel output. |
| Empty extraction (0 units) | Surface result. Ask user to confirm PDF is text-based, not scanned. |

Claude must **not**:
- Silently retry a failed extraction with modified inputs
- Generate synthetic values to fill missing fields
- Guess at cap rates, vacancy rates, or expense ratios

---

## 12. Human Review Checkpoints

At minimum, three explicit human review steps must occur before any value is treated as final:

| Checkpoint | What user must confirm |
|-----------|----------------------|
| **A — Extraction review** | Extracted unit count, column map, and missing cells in `extraction_log.json` look correct for the provided PDF |
| **B — Excel cell review** | User has filled in vacant-unit rents, expense detail, and OER assumptions manually |
| **C — Professional review** | User has confirmed with a qualified professional (不動産鑑定士 / 税理士 / 弁護士 as appropriate) before using the 収益試算値 for any formal decision |

Claude must make Checkpoints A and B explicit in its responses. Checkpoint C must be stated in every response that references a revenue estimate.

## 13. Sample-Only Validation Flow

Before any real-world PDF is used, the Skill should demonstrate correct behavior using only
synthetic sample data:

```powershell
# Step 1: Dry run with synthetic PDF
python src/main.py `
  --assumptions assumptions.sample.yaml `
  --rent-roll-pdf data/sample_rentroll_simple.pdf `
  --output ./output `
  --dry-run

# Step 2: Full run with Excel output
python src/main.py `
  --assumptions assumptions.sample.yaml `
  --rent-roll-pdf data/sample_rentroll_simple.pdf `
  --output ./output `
  --excel-output ./output/sample_direct_cap.xlsx

# Step 3: Review missing_info.md
# Step 4: Open Excel, confirm 3 sheets present, OER formulas link to 読み取りレントロール
```

This validation flow uses only files bundled in the repository.
No private PDFs, PII, tenant names, or property names are used.
